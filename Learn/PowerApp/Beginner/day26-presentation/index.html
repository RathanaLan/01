Part 3 • Workplace Crisis

The $32,000 "Isolated Feature Island" Disaster

What happens when an app has great screens, but the communication chain is severed.

What Happened at Apex Precision:

  • Developer built 3 screens: Browse, New Form, and Edit Form.
  • After tapping Submit, the New Form screen never closed or reset—it stayed frozen on old text.
  • Frustrated operators tapped Submit 5 times, creating 5 duplicate tickets.
  • Worse: The ticket sat silently in SharePoint. The maintenance supervisor in the front office never received an alert!

The Catastrophic DX Fallout:

  • 3 Hours of Silence: Machine CNC-02 sat smoking for 3 hours before anyone noticed.
  • $32,000 Missed Shipment: Turbine blades for Boeing missed the cargo flight.
  • Operator Mistrust: "The app didn't work, so I went back to paper!"

Architectural Cure: A button without feedback causes duplicates. A database without automation causes silence. Today we connect the full pipeline!

Trainer Speaking Script & Pedagogical Cues:

Emotion & Real-World Stakes (3 min): "Ask students: 'If you order an Uber, what happens if the screen doesn't show a driver and no car comes?' You get angry and close the app. Software is about human trust. When a machine breaks, the person who fixes it must be alerted automatically."

Part 6 • Power Fx Logic

The Glue Logic: Multi-Criteria Search & Filter

Allowing technicians to slice 500 tickets by machine and text query simultaneously.

🔍 The Universal Search & Filter Formula

// galWorkOrders.Items
Search(
  Filter(
    WorkOrders,
    IsBlank(cmbFilterMachine.Selected.Value) Or MachineID.Value = cmbFilterMachine.Selected.Value
  ),
  txtSearch.Text,
  "Title",
  "Description"
)
How Filter() Works Here:

If the dropdown is empty (`IsBlank`), the condition evaluates to `True` for every row, returning all records. If a machine is picked, only matching machines pass!

How Search() Wraps It:

Takes the filtered table and searches for whatever letters the user types in `txtSearch` across both `Title` and `Description`.

Trainer Speaking Script & Pedagogical Cues:

Deconstructing the Wrapper (3 min): "Teach the Russian nesting doll analogy: The innermost layer is the SharePoint table; Filter() trims rows by machine; Search() trims rows by keyword; Gallery displays the result."

Part 7 • Cloud Automation Extension

Power Automate: What Is Automation?

Child-simple definition: An invisible cloud assistant that automatically does a chore after an event occurs.

The Spark

1. The TRIGGER ("What Starts It")

A Trigger is the alarm clock that wakes the flow up. The flow sleeps quietly until this exact event happens in Microsoft 365.

⚡ SharePoint Connector:
"When an item is created"
The Chore

2. The ACTION ("What It Does Next")

An Action is the work the flow performs after waking up. It takes the data from the trigger and carries out the task.

📧 Office 365 Outlook Connector:
"Send an email (V2)"

Trainer Speaking Script & Pedagogical Cues:

First Introduction to Power Automate (3 min): "Do NOT use advanced jargon like JSON, webhooks, or variables! Keep it child-simple: Trigger = what starts it; Action = what it does next. That is the entire foundation of cloud automation."

Part 12 • Systematic Debugging

The 3-Tier Troubleshooting Audit: Where Did It Break?

When someone says "I didn't get an email!", follow this systematic sequence without guessing.

Tier A • Power Apps Layer

Did SharePoint Get the Row?

Open SharePoint list in browser. Look for the new ticket row.

✕ Row Missing: Power Apps failed to save. Check Form.Error, OnFailure, and button validation.
✓ Row Exists: Power Apps succeeded! DO NOT TOUCH YOUR APP CODE! Move to Tier B.
Tier B • Flow Trigger Layer

Did the Flow Wake Up?

Open Power Automate portal → Click Flow → Check Run History.

✕ No Runs Listed: Trigger failed to detect row. Check if Flow is turned "On" or credentials expired.
✓ Run Succeeded: Flow detected the item and woke up! Move to Tier C.
Tier C • Action / Delivery Layer

Did the Email Actually Send?

Click the run in history to inspect the "Send an email (V2)" action card.

✕ Red Exclamation: Action failed. Invalid email address or recipient mailbox full.
✓ Green Checkmark: Email sent successfully! Check recipient's Outlook Junk/Spam folder.

Trainer Speaking Script & Pedagogical Cues:

Systematic Debugging (3 min): "Emphasize this golden rule: Never touch Power Apps code if the row exists in SharePoint! Beginners waste hours breaking their apps when the issue was just a typo in an email address."

Part 12 • Demolishing Myths

3 Beginner Misconceptions Demolished

Replacing flawed mental models with enterprise engineering discipline.

Myth 1

"Power Automate replaces Power Apps"

Wrong: Thinking one is an upgrade of the other.

Reality: Power Apps is the UI (humans touch it). Power Automate is the nervous system (background cloud jobs). They work as partners!

Myth 2

"Put SendEmail() in the Button"

Wrong: Putting email code inside the button's OnSelect.

Reality: If the user closes the app immediately, the email fails! Cloud flows run 24/7 on cloud servers regardless of device state.

Myth 3

"Make separate lists for New and Edit"

Wrong: Creating duplicate tables for intake and editing.

Reality: Both forms point to WorkOrders! NewForm adds rows; EditForm updates existing rows without duplicates.

Trainer Speaking Script & Pedagogical Cues:

Myth Busting (3 min): "Drill down on Myth 2. Explain why in-app emails are fragile on mobile devices and why cloud flows provide bulletproof reliability."
