Part 6 • Power Fx Command

Command 1: EditForm() — Unlocking Data for Modification

How to transition a form into its interactive edit state.

⚙️ Function Mechanics

EditForm( frmRequest )
  • Sets Mode: Switches the form property Mode to FormMode.Edit.
  • Preserves Values: Looks at Item (e.g. galRequests.Selected) and loads all existing values into the DataCards.
  • Unlocks Controls: Converts read-only labels into editable text inputs, date pickers, and choice dropdowns.

💡 Gallery Icon Wiring Pattern

Inside your gallery template row, insert an Edit pencil icon and write:

Navigate(scrEdit, ScreenTransition.Fade)
Key Principle: Because the icon is inside the gallery row, clicking it automatically sets galRequests.Selected to that exact record!

Part 7 • Architectural Plumbing

The Core Plumbing: Form.Item = galRequests.Selected

How Power Apps tells the form which exact business record to read and modify.

🔍 The Missing Link

When you put a form into Edit mode, Power Apps asks: "Which record do you want to edit?"

frmRequest.Item = galRequests.Selected
  • galRequests is the name of your gallery control.
  • .Selected represents the active record clicked by the user.
  • It includes the primary key: Selected.ID.

⚠️ What Happens If Item is Empty?

The Dreaded "No item to display"

If a form is in Edit mode but Item is blank, the form locks all fields and says "No item to display".

This is the #1 panic point for beginners. If you see this, do not panic! Simply select the form and type galRequests.Selected into the Item formula bar.

Part 8 • Engine Decision Logic

How SubmitForm() Decides: Insert vs Update

The internal intelligence of Power Apps submission engine.

Case 1: FormMode.New

Creates Brand-New Row

  • Item is ignored (treated as Blank).
  • Issues an HTTP POST to SharePoint List.
  • SharePoint generates a brand-new unique ID (e.g. #1045).
  • Used for: Logging a brand-new breakdown.
Case 2: FormMode.Edit

Updates Existing Row

  • Reads Item.ID (e.g. ID #1043).
  • Issues an HTTP PATCH targeting that exact row.
  • Preserves original ID, Created date, and CreatedBy author!
  • Used for: Closing tickets, adding notes, updating status.

Part 9 • Safety & Resilience

The Safety Escape Hatch: ResetForm() vs Cancelling

Why enterprise applications require an explicit discard buffer command.

❌ Fragile Pattern: Navigate Back Alone
// Cancel Button
Back()
  • Leaves half-typed text trapped in the form memory cache!
  • If the operator clicks a different ticket later, the old typed text might still be lingering in the boxes!
✅ Enterprise Pattern: ResetForm + Back
// Cancel Button: btnCancel.OnSelect
ResetForm(frmRequest);
Back()
  • Wipes uncommitted typing from local memory buffer.
  • Reloads the pristine saved truth directly from SharePoint.
  • Navigates back with zero memory leakage!

Part 12 • Diagnostic Pitfalls

Common Misconceptions & Structural Traps

Three beginner mental traps that break enterprise Update workflows.

Trap 1

SubmitForm Only Creates

"SubmitForm() always makes a new row; I need a different function to update."

The Fix: SubmitForm() inspects Form.Mode. In Edit mode, it issues an HTTP PATCH update to the row in Item!

Trap 2

Item Left Blank

"Power Apps knows which row I clicked without setting Item."

The Fix: If Item is empty, the form locks with "No item to display". Always write Item = galRequests.Selected!

Trap 3

Cancel Without Reset

"I can just call Back() to cancel an edit."

The Fix: Unsaved text stays cached in memory. Always call ResetForm(frmRequest) before Back()!
