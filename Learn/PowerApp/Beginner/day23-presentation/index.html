Part 6 • Power Fx Command

Command 1: NewForm() — Wiping the Slate Clean

Why you must explicitly instruct Power Apps to prepare for a brand-new record.

⚙️ Function Signature & Mechanics

NewForm( FormName )
  • Argument: FormName — The exact name of your EditForm control (e.g. frmRequest).
  • What it does: Switches the form's mode to FormMode.New.
  • Ignores Item: Disconnects the form from Item = galRequests.Selected so you don't overwrite existing rows.
  • Resets DataCards: Blanks out all text inputs and loads SharePoint column defaults.

💡 Standard Enterprise Pattern

Always bind NewForm together with screen navigation on your '+ New' button using a semicolon ;:

// Button: btnAddNew.OnSelect
NewForm(frmRequest);
Navigate(scrFormScreen, ScreenTransition.Fade)
⚠️ Order Matters: Call NewForm() *before* Navigate() so the learner never sees a flicker of the previous record!

Part 7 • Logic & Safety

Client-Side Safety: DataCard Validation Rules

How Power Apps protects SharePoint from corrupt, blank, or malformed entries.

🛑 The Built-in Required Guard

When a column in SharePoint is set to "Require that this column contains information":

  • The corresponding DataCard automatically sets Required = true.
  • A red asterisk * appears by the card label.
  • When the user clicks submit, if the box is empty, Power Apps refuses to send the data to SharePoint.
  • The card border highlights red with: "An entry is required or has an invalid value."

🧠 Reconnecting Day 17 Logic

Remember our Day 17 mental model: Condition → True/False → Action. You can write custom button-level validation before even calling SubmitForm:

If(
  IsBlank(DataCardValue1.Text),
  Notify("Title is mandatory!", NotificationType.Error),
  SubmitForm(frmRequest)
)
Question: Is it blank? • True = Alert user • False = Submit to SharePoint!
Part 8 • Power Fx Command

Command 2: SubmitForm() — The Cloud Dispatcher

The single master command that writes local form data into persistent cloud storage.

📦 What SubmitForm Does Automatically

SubmitForm( frmRequest )
  • Scans all DataCards: Gathers every value from every text box, dropdown, and date picker.
  • Executes Client Validation: Confirms all required cards are populated.
  • Determines SQL Operation: If the form is in FormMode.New, it issues an HTTP POST (Insert). If in FormMode.Edit, it issues a PATCH (Update).
  • Zero Manual SQL: No INSERT INTO commands or complex mappings needed!

⚠️ The #1 Beginner Blunder

DO NOT put Notify() on the button!

Writing SubmitForm(frmRequest); Notify("Saved!", Success) on the button is a critical design flaw.

Why? SubmitForm runs asynchronously over the network. If the Wi-Fi drops, or validation fails, the button still blindly runs Notify("Saved!")! The user is lied to! The true notification must be anchored in the form's OnSuccess property.

Part 9 • Feedback Architecture

The Golden Hook: Form.OnSuccess vs Button OnSelect

Why enterprise applications decouple the submission request from the success response.

❌ Fragile Pattern: Button OnSelect
// Button OnSelect
SubmitForm(frmRequest);
Notify("Record Saved!", Success);
Navigate(scrGallery)
  • Fires Notify() even if the Wi-Fi cable was severed!
  • Fires Navigate() even if required Title was empty!
  • Leaves users thinking their breakdown ticket was logged when SharePoint received nothing.
✅ Enterprise Pattern: Form OnSuccess
// Form: frmRequest.OnSuccess
Notify("Ticket created successfully!", Success);
Navigate(scrGallery, ScreenTransition.Cover)
  • Fires only after SharePoint sends back an HTTP 201 Created confirmation!
  • Guarantees zero false positives.
  • Leaves the user on the form screen with red errors if validation fails.
Part 9 • Advanced Feedback

Deep Dive: Unlocking Server Metadata with LastSubmit

How to extract SharePoint's newly generated ID number immediately after creation.

🏷️ What is Form.LastSubmit?

When SharePoint saves a new row, it immediately returns the newly minted record back to Power Apps. That complete record is stored in:

frmRequest.LastSubmit

This record contains all columns, including system-generated values you didn't even type: ID, Created, CreatedBy, and Modified!

🚀 Professional Confirmation Formula

Instead of a generic "Saved!" message, show the user their exact new ticket reference number:

// frmRequest.OnSuccess
Notify(
  "Ticket #" & frmRequest.LastSubmit.ID & " created!",
  NotificationType.Success
);
Navigate(scrGallery)
Result in App: "Ticket #1043 created!" — Instant operator confidence!

Part 12 • Diagnostic Pitfalls

Common Misconceptions & Structural Traps

Three beginner mental traps that break enterprise applications.

Trap 1

Notify on Button

"I put SubmitForm on the button, so I can put Notify right after it."

The Fix: Submission is asynchronous. The button doesn't know if SharePoint accepted it. Always use Form.OnSuccess!

Trap 2

Assuming Blank = New

"If the text boxes are empty, the form automatically creates a new row."

The Fix: If mode is Edit, submitting overwrites existing rows or throws an error. You must explicitly call NewForm()!

Trap 3

ResetForm vs NewForm

"ResetForm() creates a brand new blank record."

The Fix: ResetForm reloads previously saved data. NewForm generates an empty buffer for new storage.
