Part 3 • Plain Language First

Plain-Language Concepts: 4 Key Form Terms

Understand their human role before writing Power Fx formulas or configuring properties.

The Smart Folder

1. Edit Form

Plain Language: "The digital folder on your desk."

Technical Role: A container control that communicates with SharePoint to display and edit multiple fields of a single record.

The Specific Paper

2. Item Property

Plain Language: "Which specific record folder are we looking at?"

Technical Role: The formula property (e.g. galRequests.Selected) that feeds one exact row object into the form.

The Field Box

3. DataCard

Plain Language: "One pre-printed box for one question."

Technical Role: A sub-container bundling the field title, input control, required star, and database error message for one column.

The Lock State

4. FormMode

Plain Language: "Are we reading, fixing, or creating fresh?"

Technical Role: Dictates form behavior: FormMode.View (read-only), FormMode.Edit (update existing), or FormMode.New (blank new).

Part 4 • Power Fx Scoping

Deep Dive: The Golden Property Form.Item

Why Item expects a Record, why Table names crash it, and how gallery selection creates reactivity.

The Beginner Trap

Writing Form.Item = Apex_Maintenance_Requests

Beginners often think: "The form needs data, so I will give it the SharePoint List name in Item."

✗ frmMaintenance.Item = Apex_Maintenance_Requests
// Error: Expected Record, but received Table (150 rows)!

Why it fails: A Form cannot display 150 rows simultaneously. It has only one Title box, one Machine box, and one Priority dropdown. It needs exactly ONE record.

The Correct Solution

Writing Form.Item = galRequests.Selected

The gallery's .Selected property produces the exact single row currently highlighted by the user.

✓ frmMaintenance.Item = galRequests.Selected
// When user clicks Row 1 → Form displays Row 1
// When user clicks Row 2 → Form displays Row 2

Zero Event Handlers: You don't write an OnSelect script to push data into the form. Power Fx automatically pulls the data through reactive dependency binding!

Part 4 • Advanced Customization

Unlocking DataCards & Choice Binding

Why DataCards have padlocks, how to customize them safely, and how Choices() powers dropdowns.

The Safety Padlock

Why are DataCards Locked?

When you select a DataCard, you will see a small padlock icon in the Advanced properties pane.

Why it's locked by default:

Power Apps locks cards so you don't accidentally break the automated link between the input control and the SharePoint column.

How to unlock safely: Right-click the card and select "Unlock to change properties". Now you can translate the label to Khmer (e.g. "លេខសម្គាល់ម៉ាស៊ីន") without breaking data flow.

SharePoint Choices()

How Choice Dropdowns Populate

In SharePoint, Priority is a Choice column ("High", "Medium", "Low").

DataCardValue.Items = Choices(Apex_Maintenance_Requests.Priority)

Live Metadata Sync: You never type ["High", "Medium", "Low"] manually. Power Apps queries SharePoint metadata directly. If an admin adds "Emergency / P1" in SharePoint, your app updates automatically!

Part 6 • Pitfall Prevention

5 Dangerous Misconceptions vs. Cloud Reality

Avoid these 5 common rookie mistakes before they break form data binding or corrupt records.

Misconception 1: "The Form makes a duplicate local copy of the data."

Reality: False! The form is a direct window to the SharePoint record. It does not clone data into a detached memory sandbox.

Misconception 2: "To edit a card label, I must delete the whole DataCard."

Reality: Never delete a card! Just right-click and choose "Unlock to change properties". You can modify any label safely.

Misconception 3: "Setting Form.Item to the Table name will show all tickets."

Reality: Forms only accept a single Record. A table will throw a red error: "Expected Record, got Table".

Misconception 4: "FormMode.View lets users type notes without saving."

Reality: In View mode, all input controls are locked into read-only display. Users cannot focus or open the keyboard.

Misconception 5: "I need to write an OnSelect formula to update the form."

Reality: You write zero lines on the gallery button! Form.Item = galRequests.Selected reacts automatically.
