## 🎯 Executive Summary & Architectural Creed

> **Master Directive:**
> 1. Use the existing 27-day Power Apps curriculum as the **authoritative learning foundation**.
> 2. **Do NOT replace** the 27-day curriculum.
> 3. **Do NOT randomly change** the lesson sequence.
> 4. **Do NOT remove** existing learning objectives, exercises, examples, or important explanations.

>    $$\text{UNDERSTAND} \longrightarrow \text{SEE} \longrightarrow \text{TRY} \longrightarrow \text{BUILD} \longrightarrow \text{MAKE A MISTAKE} \longrightarrow \text{FIX IT} \longrightarrow \text{APPLY IT} \longrightarrow \text{REMEMBER IT}$$

## 📐 The 27 Pedagogical Enhancement Standards

Every day across the 27-day curriculum incorporates the following 27 standards:

| # | Standard Dimension | Implementation in Curriculum |
| :---: | :--- | :--- |
| **1** | **Learning Connection** | Every lesson features a 3-Day Spiral Bridge: `Previous Lesson ➔ Today's Lesson ➔ Next Lesson`. Demonstrates why today's concept matters and how it builds on past lessons. |
| **2** | **Measurable Objectives** | Stated upfront on Slide 3: *"After this lesson, you will be able to..."* using Bloom's Action Verbs (*explain, identify, configure, build, troubleshoot, demonstrate*). |
| **3** | **Beginner-First Explanation** | Zero-knowledge assumption. Explains technical concepts in plain everyday language before introducing the formal Power Apps technical term. |
| **4** | **Visualize Every Concept** | Flowcharts, UI mockups, architecture diagrams, data-flow models, control hierarchies, and animated sequence diagrams. No purely decorative visuals. |
| **5** | **Real-World Physical Analogy** | Every abstract concept is preceded by a physical metaphor (e.g., Variable = Temporary Notepad; Gallery = Rolodex/Repeating Ledger; Filter = Sorting Sieve). |
| **6** | **Manufacturing / Business Context** | Grounded in the unified **Apex Plastics Injection Molding & Maintenance Ecosystem** (Machine downtime, Scrap reduction, Shift handoffs, Work tickets, Safety audits). |
| **7** | **Power Apps Demonstration** | Explicit 4-step sequence: `Concept ➔ Control / Property ➔ Power Fx Formula ➔ Real-time Visual Result`. |
| **8** | **Formula Visualization** | Step-by-step syntactic anatomy: `Trigger ➔ Inputs ➔ Function ➔ Condition ➔ Output ➔ UI/Data State Change`. |
| **9** | **Guided Practice ("Build With Me")** | Step-by-step instructional scaffolding where the trainer models and the learner executes concurrently. |
| **10** | **Independent Practice** | A parallel scenario requiring the student to apply the concept without trainer hand-holding. |
| **11** | **Real Challenge Task** | A novel production edge-case that forces transfer thinking rather than rote repetition. |
| **12** | **Continuous Knowledge Checks** | Distributed checks (*Predict the Result, Spot the Bug, Multiple Choice, Formula Matching*) rather than an isolated end-test. |
| **13** | **Common Beginner Mistakes** | Explicit 3-part layout: `Wrong Approach ➔ Why It Fails ➔ Correct Power Apps Approach`. |
| **14** | **Systematic Troubleshooting** | Step-by-step diagnostic workflows for invisible controls, formula errors, delegation warnings, and submission failures. |
| **15** | **Expected Result Specification** | Crystal-clear verification criteria: *"If you did this correctly, you will observe X on screen and Y in storage."* |
| **16** | **Continuous Mini-Project Progression** | A single continuous application growing across all 27 days: **The Apex Plastics Maintenance & Material Requisition App**. |
| **17** | **Active Retrieval Recall** | Lesson begins with active retrieval: *"Yesterday you learned X... Before continuing, can you explain what Y does?"* |
| **18** | **Bridge Forward** | Closes by surfacing the limitation of today's knowledge: *"You can now do X, but real systems require Y... That is why tomorrow we unlock Z."* |
| **19** | **Student "Remember This" Notes** | High-impact, compact memory anchor cards containing only essential cognitive anchors. |
| **20** | **Trainer Support Scripting** | Dedicated off-stage trainer speaking scripts, delivery cues, targeted questions, and misconception warnings. |
| **21** | **Visible Mastery Progression** | Clear 8-stage path: `Learn ➔ See ➔ Follow ➔ Build ➔ Practice ➔ Challenge ➔ Check ➔ Master`. |
| **22** | **Pedagogical Interactivity** | Live sliders, interactive truth tables, clickable tabs, formula step-throughs, and language toggles designed exclusively to improve comprehension. |
| **23** | **Responsive Design** | 16:9 widescreen presentation canvas with universal fluid scaling, mobile single-column stacking, and touch-target standards ($\ge 44\text{px}$). |
| **24** | **Curriculum Consistency** | Unified design tokens, standard Day 25 Bottom HUD, consistent color semantics, and uniform typography across all 27 days. |
| **25** | **Cognitive Load Control** | Bite-sized conceptual chunks (`Explain ➔ Visualize ➔ Example ➔ Practice`), eliminating dense textbook paragraphs. |
| **26** | **Strict Difficulty Progression** | Spiral curve: `Zero Knowledge ➔ Foundations ➔ UI Composition ➔ Logic & Variables ➔ Data Storage ➔ Full CRUD ➔ Enterprise System Integration`. |
| **27** | **Rigorous Final Quality Test** | Evaluated through the lens of a beginner with zero programming experience to guarantee zero unexplained technical jargon. |

## 🔬 The Power Fx Formula Breakdown Standard

When teaching any Power Fx formula, instructors and slides must always deconstruct the 6-stage anatomy:

```
[USER ACTION] ➔ User taps the "Submit Repair" button
      ↓
[TRIGGER PROPERTY] ➔ btnSubmit.OnSelect
      ↓
[VALIDATION GATE] ➔ If(IsBlank(txtTitle.Text) || IsBlank(drpMachine.Selected.Value),
      ↓
[FAILURE BRANCH] ➔   Notify("Please complete all required fields!", NotificationType.Error),
      ↓
[SUCCESS BRANCH] ➔   SubmitForm(frmMaintenance);
                     Notify("Ticket submitted successfully!", NotificationType.Success);
                     Navigate(scrBrowse, ScreenTransition.Fade)
                   )
      ↓
[STORAGE & UI RESULT] ➔ SharePoint row created; Screen returns to Gallery; New ticket appears!
```

## 🌐 Bilingual Khmer & English Translation Standards

To ensure complete native understanding for Cambodian learners:

1. **Keep Well-Known IT Terms Intact:**
   `Power Apps`, `Power Fx`, `SharePoint`, `Gallery`, `Form`, `Button`, `Text Input`, `Boolean`, `true`, `false`, `If`, `And`, `Or`, `Not`.
2. **Pedagogical Bridging Pattern:**
   Use `Khmer explanation (English Technical Term)` when first introducing a concept:
   * ឧទាហរណ៍៖ `អថេរ (Variable)` ៖ ការចងចាំបណ្តោះអាសន្នរបស់កម្មវិធី។
   * ឧទាហរណ៍៖ `ផ្ទាំងទិន្នន័យដដែលៗ (Gallery)` ៖ ឧបករណ៍បង្ហាញបញ្ជីកំណត់ត្រាជាជួរៗ។
   * ឧទាហរណ៍៖ `ការផ្ទៀងផ្ទាត់ទិន្នន័យ (Validation)` ៖ ការត្រួតពិនិត្យភាពត្រឹមត្រូវមុននឹងអនុញ្ញាតឱ្យរក្សាទុក។
3. **Typography Standard:**
   * Headings & Formal Titles: `Moul`
   * Subheadings & Accents: `Siemreap`
   * Body Text & Descriptions: `Battambang` / `Siemreap` (line-height: 1.85, generous padding)
   * Formula & Code Blocks: `Consolas` / `Fira Code`
