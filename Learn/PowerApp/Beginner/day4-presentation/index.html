Questions, Conditions, True & False
How an App Inspects Data to Discover Truth

An app cannot make decisions in the dark. Before it can choose an action, it must ask a question about its data. That question is a Condition, and its only possible answer is True or False.

📄

1. The Data

Yesterday's stored values: a hydraulic pressure reading, a user name, an inspection date.

❓

2. The Comparison (Condition)

The question we ask about the data: "Is Pressure > 200?", "Is Name empty?"

✅

3. The Boolean Result

The definitive verdict produced: strictly TRUE or strictly FALSE.

Core Mental Model

Plain Language: What is a "Condition"?

A condition is not an action or a decision. It is a question that yields strictly True or False.

❌ Open Questions (NOT Conditions)

Subjective Questions with Infinite Answers

Questions that ask for opinions, descriptions, or creative responses cannot be evaluated by computer logic.

"What is the operator's mood today?"
"Why did the machine make that funny squeak?"
"How do you feel about the factory temperature?"
✔ Comparison Questions (TRUE CONDITIONS)

Precise Comparisons with Only 2 Answers

Questions comparing a piece of data against a benchmark. The outcome is 100% binary: True or False.

✔ Is Pressure > 200? ➔ TRUE or FALSE
✔ Is Operator Name Empty? ➔ TRUE or FALSE
✔ Is Inspection Date < Today? ➔ TRUE or FALSE
Key Insight: True and False are not mysterious programming symbols; they are simply the two universal answers to every comparison question an app will ever ask!

Technical Grammar

The 6 Fundamental Comparison Questions

In Power Apps and Excel, every condition is formed using one of these six relational operators.

Symbol Plain-English Question Workplace Example Sample Data Evaluates To
= Is it exactly equal to? txtDept.Text = "Molding" "Molding" = "Molding" TRUE
<> Is it different from (not equal)? txtStatus.Text <> "Completed" "In Progress" <> "Completed" TRUE
> Is it strictly greater than? txtPressure.Text > 200 245 > 200 TRUE
< Is it strictly less than? txtInventory.Text < 5 12 < 5 FALSE
>= Is it greater than or equal to? txtTemperature.Text >= 100 100 >= 100 TRUE
<= Is it less than or equal to? txtDowntime.Text <= 0.5 2.5 <= 0.5 FALSE

Data Type Compatibility

The Golden Compatibility Rule for Conditions

Both sides of a comparison operator must belong to the exact same data family.

Number ↔ Number

Legal Numeric Comparisons

Both sides must be raw numbers. Use Value() to convert text digits first.

Value(txtHours.Text) >= 8.0 ➔ TRUE / FALSE
✔ Compares quantities, prices, measurements.
Text ↔ Text

Legal Text Comparisons

Both sides must be strings enclosed in double quotes.

txtRole.Text = "Supervisor" ➔ TRUE / FALSE
⚠ Never compare text to a bare number without conversion!

Mental Model Corrections

4 Common Beginner Misconceptions & Trainer Fixes

Correcting plausible but dangerous wrong mental models before they become bad habits.

❌ Wrong Mental Model #1

"True and False is the decision."

Trainer Correction: True/False is just the answer produced by a comparison question. Tomorrow on Day 5, the If() function will use that answer to make an actual business decision.

❌ Wrong Mental Model #2

"Writing = means set this value."

Trainer Correction: In Power Fx conditions, = is an inquiry: "Is Left equal to Right?". It never changes data. Changing data uses functions like Set() or UpdateContext().

❌ Wrong Mental Model #3

"True and False must be written with quotes."

Trainer Correction: Writing "true" creates a Text string. Pure Boolean logic uses bare keywords: true and false without quotes.

❌ Wrong Mental Model #4

"Conditions can execute actions by themselves."

Trainer Correction: A condition is completely passive. It evaluates truth, but it cannot send emails, save records, or navigate screens without an enclosing If() action wrapper.
