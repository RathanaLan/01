Part 4 • Syntax Dissection

Syntax Dissection 3: The Notify() Toast Engine

Communicating clearly with users using color-coded floating notification banners.

Anatomy of the Notify() Function

The Notify() function displays a temporary banner across the top of the user's screen. It takes two essential parameters:

Notify("Your Message Here", NotificationType.Error)
1. Message String (in quotes):

Text that explains clearly what happened or how to fix it.

2. NotificationType (Enum):

Controls the banner color, icon, and urgency level.

The 4 Official Notification Types

✗
NotificationType.Error (Red)

Used for validation failures, missing inputs, and blocking errors.

✓
NotificationType.Success (Green)

Used when data successfully saves or records submit to SharePoint.

!
NotificationType.Warning (Amber)

Used to alert the user of non-blocking risks (e.g. low stock).

★
NotificationType.Information (Blue)

General status tips, sync updates, and helpful guidance.

Part 4 • Multi-Field Validation

Multi-Field Validation with || (OR Operator)

Guarding against partial submissions when an app requires multiple mandatory fields.

The Real Factory Dilemma

At Apex Plastics, a support request requires BOTH the Department and the Description. If an operator types the department but leaves the description empty, the ticket is still useless!

The Business Rule:

"If the Department is blank OR the Description is blank, halt submission!"

In Power Fx, the logical OR operator is written as two vertical pipes: || (found above the Enter key on standard keyboards).

The Combined Multi-Field Guard

If(
  IsBlank(txtDept.Text) || IsBlank(txtDescription.Text),
  Notify("Both Department and Description are mandatory!", NotificationType.Error),
  Notify("Request verified! Submitting ticket...", NotificationType.Success)
)
How Power Apps Evaluates This:
  • If Dept is blank → Entire condition is True → Shows Error.
  • If Desc is blank → Entire condition is True → Shows Error.
  • Only if NEITHER is blank does it evaluate to False → Proceeds with Success!

Part 6 • Misconceptions

5 Dangerous Misconceptions vs Power Fx Reality

Avoid these 5 common beginner traps before they lead to corrupted production data.

Misconception 1: "Power Apps will automatically know a field is required."

Reality: False! Unchecked custom canvas controls will happily submit blank strings to your database unless you explicitly build validation rules.

Misconception 2: "If() needs to say = true at the end."

Reality: Writing If(IsBlank(txt.Text) = true, ...) is redundant! IsBlank() already returns true or false on its own. Keep it clean.

Misconception 3: "Notify() saves data to SharePoint."

Reality: Notify() only talks to the human eye! It displays a message banner. It never writes a single byte to database storage.

Misconception 4: "Checking one field automatically protects the others."

Reality: If you only check IsBlank(txtDept.Text), an empty Description will slip right past your guard. You must validate every mandatory input!

Misconception 5: "Validation errors should just say 'Error!'."

Reality: Poor error messages frustrate users. Great validation tells the user exactly what is missing and how to fix it immediately.
